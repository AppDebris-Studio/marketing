AIと一緒に成長する仕組みを作った
— Claude Code フックで実現するプロンプトロガー

Claude Code AI開発 フック シェルスクリプト セキュリティ

「AIは会話内容を蓄積していない」という事実から出発し、 プロンプトを自動記録・分析してAIとの協働を深化させる仕組みを設計・実装した。 トークンコストゼロ、セキュリティ考慮済み、複数AIエージェント対応。

1. 発端 — 「お互いの成長」という問い

Claude Code を日常的に使っていて、ふと気になった。 「AIは私が書いたプロンプトを蓄積していますか？」

答えはノー。各会話セッションは独立しており、終わると内容は消える。 メモリシステムはあるが、それは私が明示的に「記録して」と指示した情報だけだ。

ここで思った。機密情報以外のプロンプトをスキルで蓄積すれば、 お互いの成長に使えるのではないか？ ユーザーのプロンプト傾向を学習することで、確認の往復が減り、 初回から意図を正確に把握できるようになる。

2. 設計の検討 — 何を使えば実現できるか

Claude Code にはフック機能がある。特定のイベントに反応してシェルコマンドを実行できる。 これを活用すれば、プロンプト送信のたびに自動でログを記録できる。

時系列での処理フロー

セッション開始 └─► SessionStart フック発火（async） └─► モデル名を ~/.claude/current-model.txt に保存 ユーザーがプロンプト送信 └─► UserPromptSubmit フック発火（async） └─► prompt-logger.sh 実行 ├─► prompt-filter.sh で機密情報を [REDACTED] に置換 ├─► フィルター済みが空 → スキップ ├─► current-model.txt からモデル名を取得 └─► prompt-log.jsonl に追記

async: true を設定することで、フックの完了を待たずにClaudeが応答を返す。 会話の遅延はゼロ。

なぜ SessionStart でモデルを記録するか

UserPromptSubmit フックのJSON入力には model フィールドが含まれない。 プロンプト送信時点ではまだモデルが確定していないためだ。 そこで SessionStart フック（セッション開始時に発火）でモデル名を一時ファイルに保存し、 ロガーがそれを読み取る設計にした。

3. セキュリティ設計 — 部分置換という選択

ログ記録において最初に考えるべきはセキュリティだ。 プロンプトには機密情報が混入することがある。

ここで重要な設計判断があった。 「機密箇所を含むプロンプト全体を削除する」のか、 「機密箇所だけを置換して残りを保持する」のか。

全削除は安全だが、プロンプトの傾向分析には使えない。 部分置換（[REDACTED]）なら文脈を保ちつつ機密を除去できる。 分析価値を最大化するために部分置換を選んだ。

検出対象パターン（BSD sed + 正規表現）

カテゴリ例
APIキー・トークンsk-xxx, ghp_xxx, Bearer xxx, 32文字以上の英数字
メールアドレスxxx@xxx.xxx
電話番号090-xxxx-xxxx, +81xx
クレジットカード1234-5678-9012-3456
マイナンバー12桁の数字
パスワード記述password: xxx, パスワード：xxx
秘密鍵ブロック-----BEGIN PRIVATE KEY-----

自然文中の人名・住所は正規表現では検出できないため、スコープ外とした。 完璧なフィルタリングより、コストゼロで動く実用的な仕組みを優先した。

4. ログ形式 — 分析に必要な情報だけを記録

1行1JSONの形式（JSONL）で記録する:

{"date":"2026-03-28T14:07:03Z","model":"claude-sonnet-4-6","cwd":"/path/to/project","prompt":"..."}

date（時間帯・頻度分析）、 model（どのAIが使われたか）、 cwd（プロジェクト別分布）、 prompt（傾向分析の本体）。 この4フィールドで分析に必要な情報は揃う。

5. 運用ルール — 肥大化しない設計

ログファイルは放置すると肥大化する。 10,000行を超えたら先頭1,000行を自動削除し、9,000行から再蓄積する仕組みを prompt-logger.sh に組み込んだ。

lines=$(wc -l < "$LOG") if [ "$lines" -gt 10000 ]; then tail -n +1001 "$LOG" > "${LOG}.tmp" && mv "${LOG}.tmp" "$LOG" fi

また、ログファイルのパーミッションは chmod 600（自分のみ読み書き可）、 スクリプトは chmod 700 に設定した。

保存先はグローバルではなく ~/dev/shared/agent-skills/ai/prompt-log.jsonl とした。 複数のAIエージェントが共有リソースとして参照できる場所だ。

6. 分析スキル（prompt-analyzer）との連携

ログを蓄積するだけでは意味がない。分析して活用する仕組みが必要だ。

そこで prompt-analyzer スキルを作成した。 secretary の「整理」コマンドから自動で呼び出され、以下を実行する:

フェーズ1（トークンコストゼロ）

  • 時間帯分析 — いつ最も活動しているか
  • プロジェクト別分布 — どのプロジェクトで多く使っているか
  • 頻出語TOP20 — どんな言葉をよく使うか
  • 文体特徴 — 承認・疑問・命令の比率

フェーズ2（LLM処理・確認後実行）

  • 意図分類 — 質問/依頼/確認/承認/提案の比率
  • フィードバックパターン — 中断・修正依頼・肯定の頻度

分析結果は user_profile.md に自動反映される。 データが50件以上蓄積されたら分析が走り、50件未満はスキップされる。

今日の教訓

  • フックコマンドはシェルスクリプトに切り出す — settings.json内のクォートネストを避けることで実装の安定性が大幅に上がる
  • コストゼロから設計する — フェーズ1をshell+jqのみにすることで、日常的に実行できる仕組みになる
  • セキュリティは設計の最初に — フィルタリングルールは後付けではなく、仕組みの中心に置く
  • スキルは共有リソースとして設計する — 将来の別AIエージェントも同じログを読める場所に置くことで拡張性が生まれる
