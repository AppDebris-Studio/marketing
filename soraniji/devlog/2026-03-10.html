1. Firebase Functions パッケージ肥大化（369MB → 解消）

firebase deploy --only functions を実行したところ、EntityTooLarge エラーで弾かれた。 Cloud Functions のアップロード上限は 100MB 未満。それが 369MB を超えていた。

原因1: backend の package.json に expo・react が混入

Dev/backend/package.json に expo、react、react-native が依存として記載されていた。 これらは Node.js の Cloud Functions には不要だが、npm install で全部展開されていた。 依存から除去することで数十 MB 削減。

原因2: CocoaPods のシンボリックリンクが混入

開発中に誤って Dev/backend/ios/ が作成されており、iOS ビルド時の CocoaPods ファイル（Pods/）まで含まれていた。 rm -rf Dev/backend/ios Dev/backend/android で削除。

原因3: .firebaseignore が効いていなかった

.gitignore に node_modules/ がなく、Firebase の ignore 設定も不完全だった。 .gitignore に追加 + .firebaseignore 新規作成 + firebase.json の ignore フィールドを整備して解消。 

# .firebaseignore
node_modules/
src/
.git/
*.log

この3つを同時に修正してようやく Deploy complete! が出た。

2. JST/UTC タイムゾーンバグ — 深夜0時に上限が解除されない

日付変更線を超えた AM 0:00 JST でも「本日の投稿上限に達しました」が表示され続ける不具合。

根本原因

new Date().toISOString().slice(0, 10) は UTC の日付を返す。 JST は UTC+9 なので、JST の 0:00〜8:59 はまだ UTC の前日扱いになり、 Firestore に保存された daily_post_date（UTC日付）と一致しなくなる。

解決策: date.ts を新設してすべての日付処理を集約

// src/utils/date.ts
export function localDateString(date: Date = new Date()): string {
  return [
    date.getFullYear(),
    String(date.getMonth() + 1).padStart(2, '0'),
    String(date.getDate()).padStart(2, '0'),
  ].join('-');
}

getFullYear()/getMonth()/getDate() はデバイスのローカルタイムゾーンで動作するため、 JST 環境では JST 日付が返る。toISOString() の使用をコードベース全体で禁止し、 日付が関係する処理は必ず date.ts の関数を使うルールを CLAUDE.md に明記した。

3. EXIF 日付の Hermes エンジン非互換バグ

カメラ撮影時の EXIF DateTimeOriginal は "2026:03:10 14:32:00" 形式。 Chrome/Safari の JS エンジンでは new Date("2026:03:10 14:32:00") がなんとなく動くが、 Expo（React Native）が使う Hermes JS エンジンでは Invalid Date になる。 

// src/utils/date.ts
export function parseExifDate(raw: string | undefined): string | undefined {
  if (!raw) return undefined;
  const m = raw.match(/^(\d{4}):(\d{2}):(\d{2}) (\d{2}):(\d{2}):(\d{2})$/);
  if (!m) return undefined;
  const [, year, month, day, hour, min, sec] = m;
  const d = new Date(`${year}-${month}-${day}T${hour}:${min}:${sec}`);
  return isNaN(d.getTime()) ? undefined : d.toISOString();
}

ISO 8601 形式（ハイフン区切り）に変換してから new Date() に渡すことで Hermes でも正常動作する。

4. useMinuteTick — FlatList の setInterval 乱立を解消

PostCard は FlatList で大量に表示される。以前の実装は各カードが独立した 60 秒 setInterval を持っていたため、 カードが 20 枚あれば 20 本のタイマーが動いていた。

解決: モジュールレベルの singleton interval

// src/hooks/useMinuteTick.ts
const listeners = new Set<() => void>();
let intervalId: ReturnType<typeof setInterval> | null = null;

export function useMinuteTick(): void {
  const [, setTick] = useState(0);
  useEffect(() => {
    const notify = () => setTick((t) => t + 1);
    listeners.add(notify);
    if (intervalId === null) {
      intervalId = setInterval(() => listeners.forEach((fn) => fn()), 60_000);
    }
    return () => {
      listeners.delete(notify);
      if (listeners.size === 0) { clearInterval(intervalId!); intervalId = null; }
    };
  }, []);
}

カードが何枚あっても setInterval は常に1本。 全カードがアンマウントされたらタイマーも止まる。Firestore への通信は一切発生しない。

5. PhotoType フィルタ機能実装

虹だけでなく ☁️ 雲・🌅 朝日・🌇 夕陽・⚡ 雷 も投稿できるように。 タイムライン画面には横スクロールのフィルタチップバーを追加。

実装のポイント

  • Firestore クエリに where('photo_type', '==', photoType) を条件追加
  • フィルタ変更 = 別クエリなので TanStack Query の cache key を `Timeline:${activeFilter}` に変更
  • useCallback で fetchWithFilter をメモ化し、activeFilter が変わった時だけ再生成
  • Firestore の複合インデックス（status + photo_type + posted_at）を firestore.indexes.json に追加してデプロイ
// app/(tabs)/index.tsx（抜粋）
const fetchWithFilter = useCallback(
  (cursor?: QueryDocumentSnapshot, uuid?: string) =>
    fetchTimeline(cursor, uuid, activeFilter ?? undefined),
  [activeFilter],
);
const { posts, ... } = usePaginatedPosts(fetchWithFilter, {
  tag: `Timeline:${activeFilter ?? 'all'}`,
});

また Nominatim の逆ジオコーディング結果が海外だった場合は "Tokyo, Japan" のように {locality}, {country} 形式で表示するよう onPostProcess.ts を更新。

7. 本日の教訓まとめ

  • toISOString() は UTC を返す。日付には必ずデバイスローカルの関数を使う
  • EXIF 日付は Hermes で Invalid Date になる。正規表現で ISO 形式に変換してから渡す
  • FlatList 内の副作用は singleton パターンで集約する（タイマー、イベントリスナー等）
  • Firebase Functions のデプロイ前に node_modules サイズを必ず確認する
  • setDoc(merge: true) は指定フィールドを上書きする。カウンタの所有権は1か所に集約する
